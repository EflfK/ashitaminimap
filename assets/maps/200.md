# Garlaige Citadel map provenance

- Zone: Garlaige Citadel (`200`)
- Stock pages: `1`, `2`, `3`, `14`, and `16`
- Collision/navigation: `Garlaige_Citadel.obj` and
  `Garlaige_Citadel.nav`
- Page 1 map record: scale byte `2`, offsets `(-368,-368)`
- Page 1 calibration: origin `(368,368)`, `0.40 px/yalm`,
  `80 yalms/cell`
- Page 1 Detour elevation band: `-1` through `8`
- Page 1 verified alpha bounds: `(212,212)-(293,294)`
- Page 16 map record: scale byte `2`, offsets `(-352,-336)`
- Page 16 calibration: origin `(352,336)`, `0.40 px/yalm`,
  `80 yalms/cell`
- Page 16 Detour elevation band: `-21` through `-14`
- Live Ashita elevation rule: page 16 while player `z` is `14` through `21`
- View bounds: complete `(0,0)-(512,512)` page

Garlaige reuses overlapping world coordinates across logical pages and has
navmesh connections between areas that the stock map displays separately.
Consequently, one zone-wide connected-component projection is not a truthful
structure layer. AshitaMinimap selects structure assets by the active stock
page and currently enables authored page 1 and page 16 layers. Their
calibration and alpha registration have been checked, but complete navmesh
component classification and live route/transition audits have not been
recorded. Garlaige must therefore be treated as partial. Pages `2`, `3`, and
`14` intentionally retain vanilla-only fallback until their distinct
membership rules are verified.

```text
python tools/generate_walkable_map.py <OBJ> <NAV> \
  assets/maps/200_01_structure.png \
  --origin-x 368 --origin-y 368 --pixels-per-yalm 0.4 \
  --minimum-elevation -1 --maximum-elevation 8 \
  --exclude-box 0,0,212,512 --exclude-box 290,0,512,512 \
  --exclude-box 0,0,512,212 --exclude-box 0,298,512,512 \
  --component-report assets/maps/component-reports/200_01_structure.json
```

The page-1 elevation band includes the north entrance at live game `z=-6`
(Detour elevation approximately `+6.7`) as well as the main floor. This
observed pair confirms the opposite vertical-axis sign for this source; it is
not by itself proof of complete floor membership. The spatial trim is required
because other logical Citadel pages occupy the same elevation band and project
elsewhere on the same 512-by-512 canvas. The command uses a right exclusion at
x=290 because seam sealing and Lanczos resampling expand the final alpha; the
inspected final right bound is x=293. Its bounds were registered against the
complete page-1 parchment, not inferred from the live viewport.

```text
python tools/generate_walkable_map.py <OBJ> <NAV> \
  assets/maps/200_16_structure.png \
  --origin-x 352 --origin-y 336 --pixels-per-yalm 0.4 \
  --minimum-elevation -21 --maximum-elevation -14 \
  --component-report assets/maps/component-reports/200_16_structure.json
```

Both outputs were visually registered against their matching files in
`assets/vanilla/`. Their boundaries follow the stock accessible regions while
omitting other Citadel floors that project into the same 2D coordinate space.
This visual registration validates calibration, not complete navigable
coverage.

## Outstanding completion evidence

Before Garlaige can be called complete, record:

- a classification of every plausible navmesh component for pages 1 and 16;
- live entrance, middle, and exit coordinates for every stair, ramp, drop, and
  other transition;
- page-membership evidence and authored layers for pages 2, 3, and 14, or an
  explicit reason each page should remain vanilla-only;
- close-zoom confirmation that the player remains over structure along every
  audited route.

Minimap.dll can retain page 1 after the player falls through an upper-floor
hole. Automatic selection therefore applies the inverse of the verified
Detour band to the live Ashita elevation: player `z=14..21` selects page 16.
This rule is evaluated continuously, while an explicit `/aminimap page`
selection continues to take priority.
